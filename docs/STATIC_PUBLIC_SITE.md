# Pilot public site

The pilot builds **six static pages and 18 files**: home, contact, privacy, terms, cookie policy and 404, plus local CSS, logo/favicon, Geist font, host configuration and four required attribution files. It replaces the inherited 118-page public output. Contact and all legal pages contain literal `[FILL]` values for LMC details. They do not claim the upstream operator's identity, address, policies or service terms.

`apps/landing/astro.config.mjs` always selects `pilot/src` and `pilot-public`; there is no flag to publish the inherited routes. Active pages stay under `apps/landing/pilot/src/pages`. The existing `src/pages`, content, helpers, public assets and function sources are retained exclusively for unchanged source/history/tests. The content schema is reused for legacy type compatibility, but no pilot page imports or publishes collection entries. The original 81 unit tests and two landing source-inventory tests pass with their original assertions, including the 32-endpoint historical inventory. That source inventory is not a declaration that those endpoints are deployed.

The deployable output has no JavaScript, server/function files, analytics, tracking pixels, voice demo, blog/comparison/solution/pricing pages, search index, Markdown alternatives, API discovery or runtime/provider/database configuration. The only external navigation is the explicit LMC app sign-in link. Fonts and images load locally; all pages have one H1, noindex, and a CSP forbidding scripts, outbound connections and form submission. There are no forms. Robots disallows all crawling while placeholders remain. IndexNow/search-index publishing integrations are not enabled.

`pnpm landing:build` runs the complete-directory gate before it can succeed. The gate requires the exact page/public-asset inventory, verifies all local references, rejects inherited names/claims outside the mandatory attribution files, checks placeholders, and compares software/license notices and font bytes with their canonical sources. The gate does not ignore the old content after discovering it; it fails if any of that content enters the output. Eleven regression cases prove acceptance of the real artifact and rejection of extra articles, server functions, JavaScript/inline scripts/inline styles, external images, lost placeholders and altered notice/font bytes. Existing tests were not removed, skipped or relaxed.

Local HTTP verification passed **32 GET/HEAD positive controls**, comparing every served page/asset byte-for-byte with the output and requiring empty HEAD bodies, plus **24 GET/HEAD 404 controls** for retired article, pricing, feature, solution, French, API/discovery, logo and screenshot paths. The existing preview process was verified live and its homepage hash matched the built file before reuse. Browser QA checked desktop/mobile, local font/image load, single-column mobile layout without horizontal overflow, contact/privacy placeholders and absence of console errors. Screenshots are exported separately.

Required attribution is deliberately retained under `attributions/`: exact repository LICENSE/NOTICE/third-party notices and the Geist SIL OFL 1.1 license. These copyright notices are not LMC operator contact/legal documents. The new font credit is appended to THIRD_PARTY_NOTICES; existing notices and original LICENSE/NOTICE remain intact.

Deploy **only `apps/landing/dist/`**, separately from admin and worker. The standalone archive in the task outputs contains only the 18 static files and was extracted and revalidated with the same gate. Do not upload app/repository source, legacy `public/`, `functions/`, `node_modules` or environment files. `_headers`/`_redirects` are host-specific configuration; hosts that do not interpret them must enforce equivalent headers/redirects themselves. Production method/header enforcement still needs staging verification. No hosted deployment, final legal review or hosted CI run is claimed.

The main CI checks job now runs the artifact regression suite after its full build. The landing workflow checks the actual output and local HTTP behavior, instead of crawling legacy source/claims or installing an ad hoc preview server. Local workflow configuration tests passed. The old SEO validator remains available as `seo:validate:legacy`; the pilot validation command checks the current noindex artifact, which intentionally publishes no sitemap. Hosted execution remains an outstanding release requirement.

The SAST audit flags the intentional `<script>` negative fixture in `scripts/pilot-static.node.mjs`. One exact-rule annotation marks that single test line: it writes only into a guarded temporary copy, never serves/executes it, and requires the production artifact verifier to reject it. The test remains unchanged. No scanner rule/parser change, directory exclusion or production-code waiver was introduced.

Final verification: the unchanged exhaustive API/table test and both historical landing inventory tests passed together (three tests, zero skips/failures; exhaustive runtime 22.06s, original 120s timeout). Strict Semgrep passed 101 rules / 1,794 targets with zero findings/errors; the artifact verifier, HTTP checker, negative-fixture suite and Astro config are confirmed in scanned paths. Existing default ignore/large-file limits remain. The only new exact-rule annotation is the documented unserved negative-script fixture; no parser/rule/exclusion changes were made. Staged Gitleaks passed.
